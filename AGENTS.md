## Project Identity

IronLog is an iOS workout tracker (strength + cycling) plus a sync server.
AI-assisted training: Claude generates JSON plans, the app executes and logs
them, logs sync back to the server for analysis. Two codebases in one repo:

- `IronLog/` -- Swift / SwiftUI / SwiftData app (iOS 17+, watchOS 10+), MVVM +
  Services, XcodeGen-generated project.
- `ironlog-server/` -- FastAPI + MongoDB + Docker sync + analytics server.

The app talks to a live production server by default. There is no staging tier.

## Safety And Approvals

These prevent expensive mistakes a new agent could make in the first five
minutes. When they conflict with a canonical doc, the canonical doc wins.

1. **Commits and pushes require explicit user approval.** Work on the current
   branch (`develop`); never push to `main` directly; never skip hooks. Do not
   create a feature branch unless the user asks.
2. **Production is live with real user data.** Deploying to the VPS
   (`ssh root@v170184.hosted-by-vdsina.com`, `docker compose up --build -d` in
   `/opt/ironlog`), running `tools/backfill_*` scripts, or `DELETE` against the
   production MongoDB all require explicit approval before acting.
3. **Never commit, log, or paste secrets:** JWT secret, MongoDB credentials, the
   VPS SSH password (in shared notes). Read them from the environment only.
4. **Never hand-edit `IronLog/IronLog.xcodeproj/project.pbxproj`.** It is
   generated by XcodeGen from [`IronLog/project.yml`](IronLog/project.yml). Edit
   `project.yml` and run `xcodegen generate`.
5. **No manual plan creation in the UI.** Plans enter only via JSON import (from
   AI or server). This is a product invariant, not a missing feature.
6. **SwiftData only** (never CoreData). Persisted types keep the `SD` prefix;
   workouts reference templates/plans by string foreign key so re-import does not
   orphan history.
7. **`PlanType` must stay in sync** between server (`app/schemas/__init__.py`)
   and client (`Services/SchemaRegistry.swift`). Adding a plan type touches both,
   plus a schema under `schemas/`, plus import dispatch.
8. **Catalog slugs are immutable.** To reinterpret an exercise, deprecate it and
   create a new slug with optional `replaced_by`. Never rename a slug.
9. **Do not revert user changes or unrelated dirty files.** Touch only what the
   task requires (the working tree may carry unrelated edits and untracked
   exports).

## Setup And Commands

```bash
# iOS: regenerate the Xcode project after any project.yml or file-tree change
cd IronLog && xcodegen generate && open IronLog.xcodeproj

# Server: build and run locally (MongoDB + app) via Docker
cd ironlog-server && docker compose up --build -d
```

Server unit + route tests do not need Docker -- they run against an in-memory
fake DB (`.venv` with `requirements-dev.txt`).

## Code Style

- Swift: SwiftUI + MVVM + Services; two-layer models (JSON `Codable` +
  SwiftData `@Model`). Match the surrounding file's conventions.
- Python: FastAPI; keep pure logic in the `_`-prefixed helper modules
  (`_analytics_helpers`, `_catalog_validators`, `_exercise_doc_validators`) so it
  stays unit-testable without the app stack.
- Comments (all languages): ASCII punctuation and standard Cyrillic only -- no
  em-dash, no unicode arrows, no multiplication sign, no letter yo.
- Schema `x-schema-id` timestamps are identifiers, not free-edit fields.

## Testing And Verification

Run the narrowest useful check first, then broaden when the blast radius
justifies it.

```bash
# Server (from ironlog-server/, venv active)
.venv/bin/python -m pytest tests/

# iOS (simulator name/OS may drift -- check available simulators first)
cd IronLog && xcodebuild -project IronLog.xcodeproj -scheme IronLog \
    -destination 'platform=iOS Simulator,name=iPhone 17' test
```

Validator, analytics, catalog, and exercise-doc logic lives in pure-Python
modules with unit tests -- prefer adding a test there over a route test. For
documentation-only changes, tests are not required; check links and `git diff`.
